## 2. 字幕转写服务
- 需求：IAudioTranscriptionBackend 预留本地 Whisper 替换接口，v1 注册 OpenAI 兼容实现；流式 multipart 上传样例音频、请求 verbose_json 与 segment 时间戳；输出 Transcript/TimedText。
- 配置：优先使用分析提供商自身的转写模型（仅 OpenAI 兼容）；否则使用 Transcription:ProviderId 指定提供商，其 TranscriptionModel 优先于全局 Model。未指定全局提供商时可使用当前 OpenAI 兼容提供商配合全局 Model。密钥复用提供商保护与环境变量解析。
- Transcription:TimeoutSeconds 默认 600；MaxAudioBytes 默认 26214400。全局 ProviderId/Model 可在 appsettings 或对应双下划线环境变量中配置。模型必须支持 verbose_json 分段时间戳，不支持时明确失败。

### Q1 · 🟠 · 空音频及同源空视频切片

核实：预处理按容器时长切片，媒体进程退出码 0 与非零文件长度均不能证明存在有效媒体包。原有二次上下文切片同样存在这个入口。

采纳检测并跳过空切片的方向；未采用“仅增加 abort_on 然后使任务失败”的替代方案，因为它仍会丢失该视频剩余有效内容。也不使用固定文件大小阈值或吞掉所有 FFprobe 异常，这两种方式无法区分空流与真实媒体损坏。

实现改为在编码时通过 FFmpeg 的 stats_mux_pre 收集指定音频/视频流实际输出包。没有包则返回 null、清除本次临时文件；预处理与二次规划均跳过它。正常编码错误、超时和取消仍会传播。视频初次分段也应用同一判断，报告中未单独复现的同源视频问题已补充实测。

验证：[EmptyMediaTests](C:/code/dotnet/VideoNote/tests/VideoNote.Server.Tests/Analysis/EmptyMediaTests.cs) 使用现场生成的 7 秒视频/1.5 秒音轨、反向的短视频/长音轨，覆盖抽帧音频直传、抽帧转写、字幕转写及视频分段；有效转写只调用一次，画面和语音证据保留；音视频二次预算切片不输出空物料，临时文件清理通过。[FFmpeg 官方统计选项说明](https://ffmpeg.org/ffmpeg.html#Advanced-options)。

### Q2 · 🟠 · Gemini 请求超时

核实：工厂两个 Gemini BaseUrl 分支均写死 120000 毫秒，而管线已为每次理解/组合创建可配置 linked CTS，存在双重时限。

两处 SDK Timeout 改为 Timeout.Infinite，实际取消和期限由调用者 token 控制。没有删除管线超时保护。

验证：[GeminiTimeoutTests](C:/code/dotnet/VideoNote/tests/VideoNote.Server.Tests/AI/GeminiTimeoutTests.cs) 在真实本地 HTTP 端点立即发送响应头、125 秒后发送正文，非流式请求成功取得文本；另一个用例等待端点确实收到请求后取消，确认取消能终止等待。管线回归把 RequestTimeoutSeconds 配为 2，Gemini 流式与非流式均以明确超时错误结束。[SDK Timeout 单位说明](https://googleapis.github.io/dotnet-genai/api/Google.GenAI.Types.HttpOptions.html)。

### Q3 · 🟠 · 轮询提示与元数据恢复

核实：原 Run 每次清空 Error/Notice，详情刷新只重取任务，所以元数据请求失败后既不重试又会被显示成未配置。

新增独立 Refresh 操作和 RefreshError，自动刷新不改写用户操作 Error/Notice；刷新恢复后只清除自身错误。详情模型与模板分别记录成功加载状态，失败部分继续补取并显示“暂不可用”及自动重试提示。初次加载亦使用刷新错误通道，成功重试后可恢复。

验证：[ClientRefreshTests](C:/code/dotnet/VideoNote/tests/VideoNote.Server.Tests/Analysis/ClientRefreshTests.cs) 检查操作错误/成功通知保留及刷新错误恢复；[浏览器脚本](C:/code/dotnet/VideoNote/tests/browser/pipeline.cjs) 分别让 models/prompts 返回 503 后恢复，确认模型名称自动补齐；删除 409 文案和列表删除成功通知跨两次轮询仍保留。

### Q4 · 🟡 · 停机语义

核实：原 linked token 同时代表宿主停止和用户取消，共用 Canceled 分支。

现在优先识别宿主停止，将运行任务标记为 Failed/服务中断；已有用户取消终态仍由 Writer 保护。停机写入使用独立的 5 秒清理窗口，存储暂不可用时保留数据库状态供下次启动恢复。尚未领取的排队任务保留。

验证：[WorkerResilienceTests](C:/code/dotnet/VideoNote/tests/VideoNote.Server.Tests/Analysis/WorkerResilienceTests.cs) 实际启动/停止测试 Worker，断言运行任务为“服务停止中断”、排队任务保持 Queued、活跃注册释放。已有用户取消测试继续通过。本轮未停止或重启用户服务。

### Q5 · 🟡 · 队列存储异常边界

核实：原恢复查询、逐条恢复写入、领取查询以及失败终态写入均存在数据库异常逸出 ExecuteAsync 的路径。

对数据库读取/写入增加带取消的一秒退避重试，重建作用域，保留当前待领取任务；存储恢复后继续处理。完成结果写入可重试，但不重放模型调用。只捕获 DbException/DbUpdateException，不把未知程序缺陷一概当成暂时故障；日志仅记录异常类型。若数据库持续不可用，队列保留并等待恢复，停机可终止重试。

验证：注入 SQLite 异常分别覆盖启动读取、逐条恢复写入、领取、最终结果保存；恢复后当前和后续任务均完成，每项分析只调用一次，Worker 继续运行。

### Q6 · 🟡 · 内容过滤的部分输出

核实：旧实现只拒绝 Length，ContentFilter 可携带部分文本并继续进入持久化和汇总。

现在 ContentFilter 明确失败，不将当前部分文本保存为完整分段/报告；此前完成的分段保留，用户可查看。流式界面仍可展示已生成片段，但不会据此把任务标为完成。

验证：[PipelineFailureTests](C:/code/dotnet/VideoNote/tests/VideoNote.Server.Tests/Analysis/PipelineFailureTests.cs) 覆盖 OpenAI content_filter / Gemini SAFETY、流式/非流式、理解阶段/报告阶段八种组合；断言任务失败、无最终报告、仅保留已完整生成的分段，并且不会继续下游调用。

### Q7 · 🟡 · 轮询故障与释放

核实：旧 Poll 的非取消异常会结束周期任务，DisposeAsync 等待该故障任务时再次抛出。

将周期循环的异常边界放到每次刷新内，失败记录安全类型并继续下一轮；SignalR 触发的 Reload 也隔离回调故障。停止时终止周期，释放 Hub 放在 finally 中，避免刷新故障跳过释放。取消与组件释放异常同时发生时也能正常结束。

验证：周期回调首次抛出异常后第二次仍执行；取消与回调异常竞态不产生故障任务；真实浏览器经历失败、恢复、多次路由切换和离开页面，无 pageerror。
