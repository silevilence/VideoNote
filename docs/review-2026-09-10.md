## 2. 字幕转写服务
- 需求：IAudioTranscriptionBackend 预留本地 Whisper 替换接口，v1 注册 OpenAI 兼容实现；流式 multipart 上传样例音频、请求 verbose_json 与 segment 时间戳；输出 Transcript/TimedText。
- 配置：优先使用分析提供商自身的转写模型（仅 OpenAI 兼容）；否则使用 Transcription:ProviderId 指定提供商，其 TranscriptionModel 优先于全局 Model。未指定全局提供商时可使用当前 OpenAI 兼容提供商配合全局 Model。密钥复用提供商保护与环境变量解析。
- Transcription:TimeoutSeconds 默认 600；MaxAudioBytes 默认 26214400。全局 ProviderId/Model 可在 appsettings 或对应双下划线环境变量中配置。模型必须支持 verbose_json 分段时间戳，不支持时明确失败。
- 质量：不伪造缺失时间戳，校验有限数值、起止关系、顺序和非空文本；限制文件与响应大小；超时与用户取消分离，错误信息不包含上游响应正文或密钥。
- 验证：70 项测试全通过、0 警告；真实 FFmpeg 样例 WAV 通过本地 HTTP 协议端点验证 multipart 字段、文件长度及时间戳，覆盖 401、缺失配置、全局配置、无效 JSON/时间戳、超时、网络失败、取消和大小上限。

- 结论：可标记完成，无阻塞。按用户确认采用转写协议模拟验收。
- 协议依据：[OpenAI Audio API](https://platform.openai.com/docs/api-reference/audio/verbose-json-object?lang=csharp)。

## 4. 分段理解与报告组合
- 需求：固定 Map-Reduce 执行器已替换占位管线；按上下文预算拆分视频、帧组、音频和字幕；逐段持久化 SegmentResultsJson，汇总笔记结合创建时提示词快照生成最终报告，长笔记分批压缩后汇总。SignalR 推送分段/压缩/报告文本，详情展示流式片段及保存后的分段结果。
- 视频协议：Gemini File API 采用 resumable start→流式上传→PROCESSING 轮询→ACTIVE 文件引用；每次理解后清理文件，失败/取消时尽力清理，清理失败记录不含密钥的错误类型。上传会话 URL 不附带提供商密钥，HTTP 日志不记录临时 URL。
- 预算：Pipeline:MaxOutputTokens 默认 2048；MaxImagesPerSegment=8；ImageTokenEstimate=2048；AudioTokensPerSecond=64；VideoTokensPerSecond=512；RequestTimeoutSeconds=300。文本使用 UTF-8 字节保守估算并预留协议/提示词空间；多模态参数是可调整估算而非厂商精确计量，小窗口会增加分段。音频证据单独理解后与画面证据合并。
- 质量：逐段取消/超时、空输出、输出截断、过大物料与超长响应明确失败；最多 8 轮汇总避免不收敛；中间笔记逐段落库，旧任务迁移填入合法 []。报告以转义纯文本展示，Markdown 富渲染仍属于计划中的详情页任务。
