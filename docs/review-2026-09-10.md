## 2. 字幕转写服务
- 需求：IAudioTranscriptionBackend 预留本地 Whisper 替换接口，v1 注册 OpenAI 兼容实现；流式 multipart 上传样例音频、请求 verbose_json 与 segment 时间戳；输出 Transcript/TimedText。
- 配置：优先使用分析提供商自身的转写模型（仅 OpenAI 兼容）；否则使用 Transcription:ProviderId 指定提供商，其 TranscriptionModel 优先于全局 Model。未指定全局提供商时可使用当前 OpenAI 兼容提供商配合全局 Model。密钥复用提供商保护与环境变量解析。
- Transcription:TimeoutSeconds 默认 600；MaxAudioBytes 默认 26214400。全局 ProviderId/Model 可在 appsettings 或对应双下划线环境变量中配置。模型必须支持 verbose_json 分段时间戳，不支持时明确失败。
- 质量：不伪造缺失时间戳，校验有限数值、起止关系、顺序和非空文本；限制文件与响应大小；超时与用户取消分离，错误信息不包含上游响应正文或密钥。
- 验证：70 项测试全通过、0 警告；真实 FFmpeg 样例 WAV 通过本地 HTTP 协议端点验证 multipart 字段、文件长度及时间戳，覆盖 401、缺失配置、全局配置、无效 JSON/时间戳、超时、网络失败、取消和大小上限。
- 覆盖率：Server/Shared 行 98.36%，分支 87.92%。快速审核修复测试样例路径，使从任意测试运行目录均能定位样例。
- 结论：可标记完成，无阻塞。按用户确认采用转写协议模拟验收。
- 协议依据：[OpenAI Audio API](https://platform.openai.com/docs/api-reference/audio/verbose-json-object?lang=csharp)。

## 3. 三种模式预处理管线
- 需求：IMediaPreprocessor 输出带时长、视频分段、时间戳帧、音频切片、字幕的 PreparedMedia，并保留 materials.json 清单。直接模式使用既有 60 秒/5 秒重叠分段；抽帧模式按音频能力选择切片直传或转写；字幕模式优先软字幕，缺失/空字幕则转写。
- 质量：音频按 Ffmpeg:SegmentSeconds 分片，转写时间戳校验分段边界后换算视频绝对时间；无音轨的抽帧模式保留画面，无字幕且无音轨明确失败。物料限制在任务目录，取消贯穿 FFmpeg、转写、落盘与进度。
- 快速审核修复：输出目录检查使用 DirectoryInfo，补齐目录联接拦截。
- 验证：80 项全通过，0 编译警告/错误；修复后定向复测 10 项全通过。真实 FFmpeg 生成三段视频、约 125 帧、三段音频与软字幕；覆盖软字幕优先、无字幕转写、音频直传不转写、无音轨、取消、非法字幕与越界路径。
- 覆盖率：Server/Shared 行 91.07%，分支 81.34%（含本轮新增的源生成正则代码）。预处理各细分阶段复用已验证的 SignalR 状态写入通道，结束进度 25%。
- 结论：可标记完成，无阻塞；报告执行器于下一项组合本服务。

## 4. 分段理解与报告组合
- 需求：固定 Map-Reduce 执行器已替换占位管线；按上下文预算拆分视频、帧组、音频和字幕；逐段持久化 SegmentResultsJson，汇总笔记结合创建时提示词快照生成最终报告，长笔记分批压缩后汇总。SignalR 推送分段/压缩/报告文本，详情展示流式片段及保存后的分段结果。
- 视频协议：Gemini File API 采用 resumable start→流式上传→PROCESSING 轮询→ACTIVE 文件引用；每次理解后清理文件，失败/取消时尽力清理，清理失败记录不含密钥的错误类型。上传会话 URL 不附带提供商密钥，HTTP 日志不记录临时 URL。
- 预算：Pipeline:MaxOutputTokens 默认 2048；MaxImagesPerSegment=8；ImageTokenEstimate=2048；AudioTokensPerSecond=64；VideoTokensPerSecond=512；RequestTimeoutSeconds=300。文本使用 UTF-8 字节保守估算并预留协议/提示词空间；多模态参数是可调整估算而非厂商精确计量，小窗口会增加分段。音频证据单独理解后与画面证据合并。
- 质量：逐段取消/超时、空输出、输出截断、过大物料与超长响应明确失败；最多 8 轮汇总避免不收敛；中间笔记逐段落库，旧任务迁移填入合法 []。报告以转义纯文本展示，Markdown 富渲染仍属于计划中的详情页任务。
- 快速审核修复：历史记录迁移默认值从空字符串修正为 [] 并验证旧版本升级；优化帧规划避免反复复制全帧数组；未完成报告标注为生成片段；移除首页/导航过时的“管线未接入”文案。
- 协议验证：91 项全通过，新增旧任务迁移测试通过，末次相关 3 项复测通过；三种模式端到端模拟调用次数：视频 3 map + 1 reduce，抽帧 2 + 1，抽帧音频直传 5 + 1，字幕 1 + 1。包含真实 FFmpeg、转写 HTTP 模拟、Gemini 上传/轮询/删除、SignalR 文本与刷新持久化；长笔记触发多次汇总、非流式模型、401/400 类错误、空响应、长度截断均有测试。

## 5. 模型能力匹配规则
- 需求：Shared 的 ModelCapabilityRules 为前后端唯一匹配规则：视频→SupportsVideo，抽帧→SupportsImage，字幕→任意文本模型。音频直传仅由 SupportsAudio 启用，页面显示音轨处理方式。
- 显式覆盖：默认 API 对未匹配能力返回 400；AllowCapabilityOverride=true 时允许创建。新建页“显示全部模型”允许选择不匹配项，显示能力缺失及可能失败提示，上传脚本仅在实际主动覆盖时传入标记。协议本身不支持视频等场景仍在执行阶段给出明确错误。
- 质量：保留模式切换/关闭覆盖时清除不再可见的模型；仍校验所选模型存在；上传期间模型被删除的回滚测试保留，并改用匹配模式验证原有竞态。
- 验证：99 项测试全部通过，0 失败/跳过、0 编译警告/错误；7 组 API/UI 规则组合覆盖视频/图片/字幕及显式覆盖，音频分流沿用预处理测试。Server/Shared 行覆盖率 91.83%，分支 82.06%。
- 浏览器：三模式候选切换、覆盖警告、实际上传 URL 携带 allowCapabilityOverride=true 且返回 201 均通过；随后重新通过实时文本→报告→刷新持久化→列表→取消流程，桌面/移动端无 pageerror。
